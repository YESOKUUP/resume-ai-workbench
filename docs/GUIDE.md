# 简历 AI 工作台

把简历改成"这个岗位想要的样子"——AI 只提建议，改不改你说了算。

一个跑在**你自己电脑上**的简历工作台：导入 PDF → 核对结构 → 按目标 JD 评估改写 → 预览 → 导出 PDF。
简历、JD、API Key 全部留在本机；只有调用 AI 时，简历文本才会发给你**自己配置**的模型服务商。

---

## 一、三分钟开始用

### 1. 启动本地服务

双击 **`start.bat`**。

会弹出一个黑色窗口（那就是服务本身，**别关它**），并自动打开浏览器到 `http://127.0.0.1:8420/`。

窗口里会打印自检信息，像这样：

```
  简历 AI 工作台 · 本地服务  v2.0.0-phase2
  ----------------------------------------------------
  访问地址   http://127.0.0.1:8420/
  Python     3.13.14
  PDF 解析   ✓ pypdf
  导出 PDF   ✓ msedge.exe
  AI 配置    ○ 尚未填写 API Key（去页面右上角 ⚙ 设置）
  ----------------------------------------------------
```

**要用完就直接关掉这个窗口**（或用 Ctrl+C）。

### 2. 填 API Key

点右上角 **⚙ 设置** → 选服务商 → 粘贴你的 API Key → **测试连接**。

- 没有 Key？去服务商官网申请（DeepSeek / 智谱 等都有免费额度）
- Key 存在本机 `config.json`，**不会**被本工具传到任何地方；页面本身也从不接触它
- Base URL 与模型名收在「高级选项」里，一般不用动
- 单次输出的长度上限由服务端自动决定（按服务商取值），网关若不接受该参数会自动去掉重试；
  要手动指定就在 `config.json` 的 `llm` 下加 `"max_tokens": 8192`

### 3. 用起来

- **想先看看长什么样** → 点「用样例简历试一遍」（内置脱敏样例，零风险）
- **用自己简历** → 把 PDF 拖进去；扫描件（图片型 PDF）读不出文字，会提示你改用「粘贴简历文本」
- **核对页**：左侧是 PDF 原文，右侧是**还原出来的简历**（真实排版，能直接看出识别对不对）。标黄/标红的字段是 AI 拿不准的地方，点一下就能改；漏掉的章节点底部「+ 添加遗漏的章节」补上
- 进工作台后，**右侧「目标 JD」框里粘贴岗位 JD** —— 这是最关键的一步
- 点 **再次评估**：规则检查（数字守恒 / STAR / AI 腔）本机即时出结果，AI 建议逐条流式出现
- 逐条接受 / 修改 / 拒绝，或点「接受全部安全项」（**数字告警项永远不会被批量接受**）
- 点 **导出** → PDF / HTML / 纯文本 / 优化报告

### 4. 改简历（工作台 · 编辑模式）

简历纸本身就是编辑器，**不编辑时纸面是干净的**（手柄只在悬停时出现）：

| 想做什么 | 怎么做 |
|---|---|
| 改文字 | 点任意文字直接改（姓名 / 电话 / 邮箱 / 求职意向 / 单位 / 日期 / 每条 bullet） |
| 加一条 | 该段 bullet 列表末尾点 `+ 添加一条` |
| 删一条 | 鼠标移到那条 → 点 🗑 |
| 加章节 | 简历最底部点 `+ 添加经历 / 章节`（如"专业技能""科研课题"） |
| **改章节名** | 编辑模式下**直接点章节标题**就能改（如把「科研课题经历」改成「科研项目」），改完立即生效 |
| **调模块顺序** | 编辑模式下，章节标题右侧的 **`↑ ↓`** —— 点几下就能把「科研课题经历」提到「工作经历」前面（已到顶/到底的那个箭头会置灰） |
| **调项目顺序** | 每个单位/项目标题右侧也有 **`↑ ↓`**（同上，可把某个项目提到本模块最前） |
| 删整段经历 / 整章 | 鼠标移到单位标题 / 章节标题 → 点 🗑 |
| 调顺序 | 在要点**行首那一侧**（圆点 / `⠿`，约 26px 内）按住上下拖；或点该条**右上角的 `↑ ↓`**（悬停出现）。在文字上按住拖是"选中文字"，不会排序 |
| 复制一条 | 点中那条 bullet → 下方出现操作条 → `⧉ 复制一条` |
| 换章节 | 点中那条 bullet → 操作条里「移到」选目标章节 |
| **给文字加粗** | 选中要强调的字 → 操作条点 **`B 加粗`**，或直接 **Ctrl/Cmd+B**（再按一次取消） |
| **单独改某一段** | 点中那条 bullet → 操作条点 **`✨ 用指令改`**；单位标题 / 章节标题旁也有 ✨（见下方「指令式改写」） |
| **操作「项目介绍」** | 点一下**项目介绍**那段文字 → 出现和要点一样的操作条：`✨ 用指令改` / `B 加粗` / `⧉ 复制为要点` / `移到…` / `🗑 删除` |

> 改动都会进撤销栈（Ctrl+Z / Ctrl+Y）。**删掉带 AI 建议的条目**时，该条建议会自动作废、不再计入数字守恒——不会出现"盯着一处简历里已经不存在的数字反复报警"。
> **加粗只影响排版，不改一个字**：数据里存的是字符区间，AI 改写 / 数字守恒 / 模板导出照旧按纯文本处理。

## 二、它到底做对了什么（和普通"AI 改简历"的区别）

| | 说明 |
|---|---|
| **保真边界明确** | 允许"包装"（把已有动作展开成产出物、围绕 JD 命名机制、动词升级）；**禁止"编造"**（新增数字 / 经历 / 关键能力） |
| **PDF 解析靠几何，不靠 AI** | 用**坐标 + 字号 + 颜色**重建结构：折行自动合并、章节标题 / 条目 / 角色 / 日期分得开、连原简历里 logo 徽章那个字符都不会混进单位名。**列表符号是"画"出来的小圆点照样认得出**；**长 bullet 折成三行也能拼回一条**（见下方「PDF 解析」） |
| **数字守恒是硬栏杆** | 服务端独立复算：AI 产出里出现原文没有的数字 → 立刻告警，并**排除在批量接受之外** |
| **统一的「AI 改写风格」旋钮** | ⚙ 设置里**一个默认力度**（保守保真 / 标准 / 大胆 / 放手），**逐条评估**和**深度重写**都继承它，各自操作时又能临时改。切到「大胆 / 放手」即"放开改写"，AI 可补量化数字 / 补全经历，全部标色待你核实 |
| **纯规则体检（不调 AI）** | ⚙ 设置里一个独立开关：评估时只跑本机数字守恒 / STAR / AI 腔检查，**完全不发模型**，零额度、秒出 |
| **项目经历整段重排** | 顶部 **「🪄 深度重写」** 把**整段项目经历**按 JD 重写 + 重排顺序，三档力度可选（标准 / 狠一点 / 激进补全）。每条带**色标**（真实 / 换角度 / 推断数字 / 推测经历），逐条核对删改后再落地成独立版本。每个项目都可**展开「对比原文」**，看清到底改了什么 |
| **指令式改写（指哪改哪）** | 选中**一条要点 / 一段经历 / 一个章节** → 说一句要求（"缩短到两行以内""按 JD 的『数据驱动』重写"）→ AI **只改这一段**。结果给**原文 vs 改写**对比、可接受 / 拒绝 / **再改改**（在上一版基础上迭代），确认后才写回。像 vibe coding 一样改简历 |
| **按 JD 决定改哪些、怎么排** | 教育 / 荣誉 / 获奖 / 证书 / 其他**不参与 JD 改写**（事实性内容，改了反而假），但仍作为上下文；评估后 AI 可给出**章节与项目的推荐顺序**，右侧点「应用顺序」即可重排（可撤销 / 回滚） |
| **项目结构固定三层** | 项目介绍（一段）→ 项目工作（分组标题）→ 二级要点；**深度重写 / 指令式改写 / 导出 / 套模板都保持这个层级**，不会把二级要点压平成一级。「项目工作：」**恒为独立一行**：粘在介绍末尾的、和正文写在同一行的（`项目工作：评估原有系统…`），解析与渲染时都会拆成「标题 + 正文要点」 |
| **重写后还能继续手动改** | 深度重写落地时**保留每个项目原来的 id**（按项目名认回来）—— 重写后仍可 `↑↓` 排项目、`✨` 整段改写、点「项目介绍」出浮条。旧版本留下的「没有 id 的项目」会在渲染时自动补齐，不用重新导入 |
| **正文手动加粗** | 选中文字按 **Ctrl+B**（或操作条 `B` 按钮）就能加粗/取消，导出与套模板都保留；数据存字符区间，不污染文本 |
| **AI 加词高亮** | AI 新增的词用蓝色下划线标出 —— 一眼分清"我写的"和"AI 加的" |
| **不写死关键词** | 要求语义对齐（允许近义/上下位/相关词族），而不是把 JD 的词硬塞进去 |
| **规则与 AI 分层** | 规则层本机毫秒级、实时刷新；AI 层手动触发，避免每敲一个字就调模型 |
| **失败不丢数据** | 评估中断/限流/超时 → **已完成的建议保留在页面上**，可重试 / 保留 / 降级纯规则 |
| **可回溯** | 每次评估存快照，记录模型名与**实际发送的温度**；可回滚 |
| **简历完全可编辑** | 点任意文字就地改；`+ 添加一条`／`+ 添加经历 / 章节`；悬停出现 ⠿ 拖拽排序、🗑 删除；选中后 `⧉ 复制一条`、`移到其他章节` |
| **核对页看得见样子** | 导入后右侧直接渲染**真实简历纸**（与导出同款样式），一眼看出识别对不对；低置信字段就地标黄/标红 |
| **导出优化报告** | 6 段结构（总览/诊断/改动清单/优化后简历/投递建议/方法论）的可分享 HTML / Markdown，可发给教练/朋友看 |
| **报告不调 LLM** | 报告纯靠本机 state + 5 项验收结果拼装，**不消耗 AI 额度**，导出零等待 |

## 三、需要什么环境

| 项 | 要求 | 说明 |
|---|---|---|
| Python | 3.9+ | 服务本体**零第三方依赖**（只用标准库） |
| pypdf | **已内置** | 放在项目的 `libs/` 里，启动时自动挂载 —— 所以你机器上**任何** Python 都能读 PDF，不用 pip install |
| PyMuPDF（**强烈建议装**） | 约 53 MB | 装了就启用**几何结构解析**（折行合并 / 标题识别 / 图标剔除）。不装也能跑，但会退回"纯文本 + 猜测章节名"，结构容易错。见下方一节 |
| 浏览器 | Edge 或 Chrome（近两年版本） | 导出 PDF 用它的无头模式 |
| 操作系统 | Windows | 导出链路依赖本机 Edge/Chrome |

> **为什么把 pypdf 放进项目而不是让你装？** 你机器上可能有多个 Python，`start.bat` 恰好的那个未必装了库。
> 所以把库随项目带着，`libs/` 一起拷贝就行。
> 如果 `libs/` 被误删，用任意 Python 恢复：`python -m pip install --target libs pypdf`
>
> 体积：源码约 1.6 MB（外加 2 MB 字节码缓存 `__pycache__`，是 Python 自动生成的，可随手删掉，不影响功能）。

### 让 PDF 解析变准：装一次 PyMuPDF

**为什么值得装**：不装的话，PDF 只能靠 `pypdf` 拿"一串文字"。文字流里没有坐标、没有字号，于是——

- 一条要点被折成 3 行 → 被当成 3 条要点
- 章节标题和正文长得一样 → 只能靠硬编码的章节名列表猜（遇到"个人优势""自我评价"就失效）
- 原简历里 logo 徽章那个字符（如蓝底白字的「联」）会被当正文，单位名变成"联 某通信设计院…"
- 双栏 PDF 的左右栏顺序可能是反的

装了 PyMuPDF 后走的是**几何解析**：每个字都带坐标、字号、字体、颜色，结构是从**版面**读出来的，不是猜的。装一次就行：

```bash
python -m pip install --target D:\workbuddy\temp\pylibs pymupdf
```

装完重启服务。三个位置会被自动搜索：`<项目>/libs/` → `D:\workbuddy\temp\pylibs` → 系统已装。
想确认是否生效：打开 `http://127.0.0.1:8420/api/health`，看 `structured_ok` 是不是 `true`。

> **53 MB 太大不想装？** 也完全可以 —— 解析质量会降一档，但流程照走，核对页里改一下就行。
> 或者把它放进项目的 `libs/` 目录，让它随项目走（拷贝给同事也一样能用）。

> 端口默认 **8420**（避开常被占用的 3000/8000）。要换端口：`set RW_PORT=8531 && start.bat`

### 有多个 Python 时指定用哪个

`start.bat` 默认按 PATH 顺序找第一个能跑的 Python。想指定：

```
set RW_PYTHON=D:\Python\python 3.11\python.exe
start.bat
```

> **注意**：`libs/` 让任何 Python 都能读 PDF，所以换解释器不影响 PDF 导入。
> 想确认当前跑的是哪个解释器：服务启动的自检信息里会打印「解释器」一行，
> 或者浏览器打开 `http://127.0.0.1:8420/api/health` 看 `python_exe` 字段。

### 端口被占了会怎样

`start.bat` 会检测到并提示三种处理办法；如果你直接双击了两次，第二个实例会**主动退出并说明原因**（不会出现两个服务同时监听、请求随机落到其中一个的诡异状况）。

## 四、数据去哪了（诚实版）

**全程本机**：简历文件、结构快照 `snapshots/`、操作日志 `logs/`、配置 `config.json`、导出产物 `export/`

**出本机**：只有调用 AI 时发送的「简历文本 + JD 文本 + 指令」——仅你配置的服务商可见，本工具不另存副本。
页面上的 AI 调用透明卡会显示"本次发送了什么、发给谁、用什么模型和温度"，每次评估也都写一条日志可供回查。

```
│  ├─ pdf2html.py          PDF → JSON + HTML + TXT（人眼核对解析对不对）
│  ├─ templates.py         内置模板库（3 套样式 · 数据与样式分离）
│  └─ render.py            JSON → 套模板 → HTML / PDF
├─ server/                 本地服务（纯标准库）
│  ├─ app.py               HTTP 路由 + SSE 转发
│  ├─ llm.py              LLM 客户端（OpenAI 兼容 / 流式 / 温度折算 / 错误分类）
│  ├─ prompts.py           提示词（复用 resume-polisher + resume-jd-tailor 的方法论）
│  ├─ rules.py             规则引擎（与前端逐条等价的数字守恒 / STAR / AI 腔 / 长度）
│  ├─ docio.py             PDF 提取（挂载 libs/ + 几何结构解析）+ 调浏览器导出 PDF
│  └─ store.py             配置 / 日志 / 用量 / 快照
├─ config.json             首次保存设置后生成（含 API Key，明文，仅本机）
├─ logs/  snapshots/  export/
└─ temp/                   开发与测试用的中间产物（可删）
```

> 拷贝/迁移这个工具时，**整个文件夹一起拷**（`libs/` 别落下），或者用 `python -m pip install --target libs pypdf` 重新补上。

## 六、单独的 PDF → HTML 工具

不想开整个应用、只想先看看"这份 PDF 能不能被正确解析"时用它：

```bash
python tools/pdf2html.py 我的简历.pdf -o out/
```

产出三份：

| 文件 | 用途 |
|---|---|
| `我的简历.json` | **结构化结果**（sections → blocks → bullets，带稳定 bid）。这份就是"可编辑 HTML 简历"的数据源，工作台可直接消费 |
| `我的简历.html` | 单文件网页，三个视图：**解析结果**（语义化简历）/ **版面核对**（PDF 原页上把每行按判定角色上色）/ **纯文本** |
| `我的简历.txt` | 纯文本对照，便于 diff |

**版面核对**视图是核心：左/上是 PDF 原页渲染，每个文字块叠一个彩色框，颜色代表它被判成的角色——

| 颜色 | 角色 |
|---|---|
| 紫 | 章节标题（工作经历 / 项目经历…） |
| 青 | 条目标题（单位 / 项目 / 学校） |
| 橙 | 角色（产品经理助理） |
| 蓝 | 日期 |
| 灰 | 要点 / 条目简介 |
| 玫红 | 图标字符（logo 徽章） |

哪一行颜色不对，就说明那里判错了 —— 一眼定位，不用猜。

常用参数：`--dpi 150`（渲染更清晰）、`--json-only`（只要 JSON）。

> 这个工具**不调用任何 AI**，纯几何计算，所以结果稳定可复现。它是整个流程的"阶段 1"，产物直接喂给工作台。

### 解析为什么准：几何取字 + 模型判构

一句话：**字符交给几何（100% 准），版式判断交给模型（换模板不会崩）。**

因为这两件事的难度恰好是反的：

- **取字**：从 PDF 文本层直接读出来的字符不存在"认错"；而视觉/语言模型反而会读错
  （实测把 `–` 读成 `-`、把学校名多打一个字）。所以**绝不让模型去认字**。
- **判构**：手写规则换个模板就崩（三种模板就崩了两次）；而"看版面猜结构"正是模型的强项。

所以流程是三步：

**① 几何提取** → 每一行整理成带行号的**版面描述表**（纯文本）：

```
[1] 16.5pt 粗 +70.5 #111827 「林 晓」

[2] 9.4pt 粗 顶格 #111827 「工作经历」
[3] 9.4pt 粗 顶格 #111827 「某通信规划设计院 · 解决方案交付工程师2023.07 – 至今 · 北京」
[4] 9.4pt 细 +13.5 #111827 「售前支撑与竞品分析：…」
```

**② 模型判构** → 把这张表给它，**只让它回答"第几行是什么"**：

```json
{"name": 1,
 "sections": [{"title": 2, "entries": [{"head": [3], "bullets": [4, 5]}]}]}
```

**③ 按行号取原文组装** —— 一个字都不生成。

这样一次解决四件事：

| 收益 | 为什么成立 |
|---|---|
| **数字守恒天然成立** | 模型压根没机会写数字，不存在"编造 30+ 商机"这种事 |
| **不会认错字** | 文字永远取自原文 |
| **换模板不再崩** | 模型看的是版面，不吃字号/颜色那套特征 |
| **更省** | 模型只吐行号，2 页简历几百 token |

**三道闸门保证不静默出错**（任一不过就降级回几何规则，并在界面上说明原因）：

1. 行号必须合法（在 1..N 内，不许字符串/布尔冒充数字）
2. 覆盖率不低于 45%（整块漏标说明模型没干好）
3. 组装结果必须有章节、有条目，不能是空壳

降级链：**AI 判构 → 几何规则 → 粘贴文本 / 传 Word**。
任何一步失败都不会让你看到空白页，也不会悄悄换一套逻辑不告诉你。

> 想关掉 AI 判构：`config.json` 里把 `llm.struct_ai` 设成 `false` 即可。

### 章节标题怎么认出来的（三类模板都要覆盖）

这是踩过最深的坑：**"章节标题"在不同模板里长得完全不一样**，只按一种特征写判据，
换个模板就一个标题都认不出（→ 0 章节 → 用户看到空白）。

| 模板族 | 正文字号 | 章节标题 | 可用的判据 |
|---|---|---|---|
| A · 彩色标题 | 12.0pt | **17.2pt + 蓝色** | 字号 ≥ 正文 × 1.25（最确定） |
| B · 纯黑稍大标题 | 9.0pt | **10.5pt + 加粗** | 字号 × 1.06 + 加粗 + 短 + 顶格 |
| C · 与正文同字号 | 9.4pt | **9.4pt + 加粗** | 加粗 + 短 + 不以「：。，」结尾 + **命中已知章节名** |

判据是多信号组合（满足任一即可），另有两个硬前提：

- **该行没有日期** —— 带日期的短加粗行是「条目标题」（单位/项目），不是章节
- **不以「：」结尾** —— 「项目工作：」这种是子标题，不是章节

其它同类坑（都见过真实样本）：

- **行距不能只按"同一 block 内相邻行"估** —— 有的模板每一行都是独立 block，那样根本没有样本。
  改成"所有相邻 y0 差里出现次数最多的那一簇"。
- **折行合并不能依赖 block 边界**（同上原因），只能靠"同缩进 + 间距≈行距 + 上一行没写完"。
- **`Part` 的代表字号取"最大的"而不是"字符最多的"** —— 「单位名(9.4pt 粗) + 日期(8.2pt 细)」
  这种混排部件里日期字符更多，取错会导致单位名被当成角色、日期重复出现两次。
- **"解析不出结构"必须报失败** —— 曾经 0 章节被当成功，用户看到一片空白
  （`pdfstruct.quality()` 就是这道闸门）。

`temp/fixtures/` 里放了三类模板各一份样本，测试会逐份验证 —— 换模板不再靠运气。

### 列表符号与折行：两条最毁结构的错误，各堵一个

**① 列表符号可能是"画"出来的，文字层里根本没有「•」。**
很多简历的 bullet 小圆点/小方块是矢量图形，不是字符 —— 只靠文本正则永远识别不到，
那些要点就会被判成"顶格的简介"，结构全乱。

解法（`page_markers` / `annotate_bullets`）：用 PyMuPDF 取页面上的**小尺寸矢量图形**
（宽高都在 1–9pt 之间），凡是"垂直中心落在某行内、且紧贴该行文字左界左侧"的，
就把那一行标成列表项。判据**全部相对该行自身**，不依赖页面版心 ——
否则"bullet 文字比版心更靠右"时会漏判。

**② 一条长 bullet 折成三行，容易被当成分段。**
这是最致命的：PDF 里明明是**同一条要点的换行**，解析出来却变成三条独立要点。
根因在"折行合并"的判据上——续行往往与**正文左端**对齐，而首行左端把项目符号也算进去了，
左右差出 5~10pt，就被判成"不同缩进"；续行本身又没有符号，容易被判成另一种角色。

解法（`merge_bullet_continuations`，bullet 专属，排在通用折行合并**之前**）：

| 条件 | 取值 |
|---|---|
| 首行是 bullet，续行是 bullet / 简介 | 都行（**不要求续行自己像 bullet**） |
| 垂直 | 紧跟其后，间距 ≤ 1.45 倍行距 |
| 水平 | **宽松容差** ≤ max(6, 2.5×字号) —— 接得住"符号位 vs 正文位"的偏差 |
| 上一行没写完 | 不以 。！？ 结尾 |
| 本行不是新条目开头 | 不以日期区间 / 项目符号开头，也不是章节或条目标题 |

护栏都在测试里钉着（第 30 套）：上一行已收尾、下一行带符号、间距过大、下一行是标题、
水平错位过大 —— 一律不合并。

> 思路借鉴了另一个项目（`找工作助手/v2/backend/converters/pdf_reconstruct.py`）里
> "矢量符号检测 + 宽松续行合并"的做法。我们**只借几何子例程**，
> 保留自己"几何取字 + 模型只判行号、零写字"的架构（数字守恒的根基）。

**③ 两层缩进：`bullet.level`。**
同一 block 内按 x0 聚类出 1 / 2 / 3 级 —— 原 PDF 里「项目工作：」是 1 级，
它下面「市场与竞品分析…」等缩进更深的条目是 2 级。解析结果写进 `bullet.level`，
工作台、导出 HTML、六套模板都按层级递进缩进（2 级 +16px），不会再被压平到同一行首。

**④ 简介折行不能被切成要点。**
「项目介绍：…」折行后，后一行丢掉了前缀，容易被独立判成「要点」。
`merge_wrapped` 现在允许「简介 ↔ 要点」互相续接（仍要求同缩进、紧行距、上一行没写完），
并且中文拼接**不插空格**（`_join_text`）—— 避免「大应 / 用”体系」这类被空格制造的错行。

### 一个旋钮管两处：AI 改写风格（⚙ 设置）

早期版本里，"逐条评估"和"深度重写"各自有一套力度档位（纯规则 / 轻度 / 重度 / 放开改写 vs 标准 / 狠一点 / 激进补全），
用户很容易困惑"到底谁说了算"。现在**统一成一个旋钮**：

- ⚙ 设置里的 **「AI 改写风格」** 有四档：**保守保真 / 标准 / 大胆 / 放手**。
- **逐条评估** 和 **深度重写** 都**默认继承**这个风格 —— 你只理解"一个默认力度"。
- 每次操作又能**临时偏离**：深度重写的弹窗里直接选另一档；逐条评估的力度跟随设置（要改去设置里调，或开"纯规则体检"）。
- 切到 **「大胆 / 放手」** 即等于过去的"放开改写"：AI 可补量化数字、补全经历，全部标色待你核实。

另外有一个**独立开关「评估时仅纯规则体检」**：打开后逐条评估**完全不调模型**，只跑本机规则体检，零额度、秒出 ——
适合想先看看"数字守恒 / STAR / AI 腔"有没有问题、又不想花 AI 调用的时候。

### 放开改写：让 AI 大胆改，但不让它偷偷改

前三档（保守保真 / 标准）都守同一条底线：**不能新增原文没有的数字**。
这保证了"AI 只改表达、不编事实"，但代价是 —— 你写"提升效率"就只能留着"提升效率"，
AI 不敢补"约 30%"。

**把风格切到「大胆 / 放手」就解除了这个限制**（工作台 ⚙ 设置 → AI 改写风格 → 选「大胆」或「放手」）。松开之后 AI 可以做这些：

- 新增量化数字（"提升效率" → "效率提升约 30%"）
- 重组句子结构、合并或拆分要点
- 换更专业的说法、把一笔带过的动作展开成「动作 → 方法 → 结果」

但**仍然不许凭空多出一段没写过的经历**（公司 / 岗位 / 项目 / 证书）。
这条不是"表达限制"，是防伪造履历 —— 补一个数字你扫一眼就能判断真假，
多一段"在某某大厂做过增长"你可能没注意，面试当场穿帮，代价是 offer。

**放开之后靠三件事兜住风险：**

| 机制 | 说明 |
|---|---|
| **推断值必须登记** | 提示词强制要求 AI 把每个"推断出来的、原文没有依据的"值单独列出并给出依据（`inferred_facts`）。漏登记等于误导，比不改更糟 |
| **界面改成「待核实」而不是「必改」** | 数字守恒那一行从红色 ✕ 变成橙色 ⚠，文案是「AI 新增 N 处 · 待核实」。**明细清单照旧全列**（那是我们算的，权威） |
| **产物单独成版** | 点右栏「✨ 生成 AI 改写版」→ 先把当前状态存成「**原文版**」，再把建议全部应用并另存为「**AI 改写版**」（自动标为里程碑，不会被版本淘汰）。两版在「版本」里随时切回 |

导出的文件名会带上 `-AI改写版` 后缀，落到磁盘上也能一眼认出这是改写产物。
导出前还会再提醒一次有多少处 AI 推断的数字没核实。

> 一句话：**放开的是「表达与量化」，不放开「经历本身」**；放开的部分全部登记在案，
> 让你能逐条核实，而不是替你把关。这条边界有测试钉着（第 19 套）。

### 深度重写：整段重排项目经历（顶部「🪄 深度重写」）

上面那个「放开改写」是**逐条**改写（一条 bullet 对一条 JD 职责），好处是可控，
但改出来往往"只动了几个词"。**深度重写**换一种做法：**先通读你的全部项目经历，
再按目标 JD 把整段项目经历重写 + 重排**（项目顺序按契合度排、要点用 JD 的语言重讲）。

**三档力度，默认跟随「AI 改写风格」（也可在弹窗里临时改这一次）：**

| 风格档 → 深度重写档 | 允许做什么 | 标签 |
|---|---|---|
| **标准 · 保真重排** | 只换角度、换 JD 语汇、重排顺序、重组句式 | 真实 / 换角度 |
| **狠一点 · JD 强化** | 在标准之上：可补**合理量级**的量化数字（"提升效率"→"约 30%"）、动词升级 | + 推断数字 |
| **激进补全 · 可补全** | 在狠一点之上：可补全"可能做过但没写"的合理细节（如沉淀 SOP、开展培训） | + 推测经历 |

激进档的用意：**有些事你可能做过只是没写、有些地方能量化只是你没意识** ——
AI 先大胆补出来，**你再来判断真假**。

**关键机制：每条 bullet 都带色标，你逐条判真假后才落地。**

| 色标 | 含义 | 你要做的 |
|---|---|---|
| 🟢 **真实** | 你原文就有的事实 | 留着 |
| 🔵 **换角度** | 同一件事换 JD 的说法 | 留着 |
| 🟠 **推断数字** | AI 推断的量级 | 填真实数，或删掉 |
| 🟣 **推测经历** | AI 推测你可能做过 | 确认做过就留，没做过就删 |

**结果上屏后是一个核对面板**：每条都能勾选保留 / 删除、直接改文字、改标签。
确认后点「应用到简历」→ 当前状态先存成「**原文版**」，改写结果另存为「**AI 改写版 · 深度重写**」（标为里程碑），
两版在「版本」里随时切回、可回滚。

> ⚠️ 红线依旧：**绝不新增**你没写过的公司 / 学校 / 证书 / 时间区间。
> 服务端还有一道**本机安全网** —— 模型即便自称某条是「真实」，只要里面出现原文没有的数字，
> 会自动**降级为「推断数字」**并补上说明，防止你把 AI 编的数字当成自己写的。
> 这条链路有测试钉着（第 21–23 套）。

> 与「放开改写」的区别：放开改写是**逐条建议**（可接受/拒绝），深度重写是**整段产出**
> （可重排、可拆并，直接替换项目经历那一章）。两者都保留原文，按需要选用。

### 指令式改写：指哪改哪（选中一段 + 说一句要求）

上面三条 AI 路径都是"AI 觉得该怎么改"（逐条评估 / 深度重写 / 放开改写）。
**指令式改写**反过来：**改哪一段、改成什么样，全由你说** —— 像 vibe coding 一样改简历。

**怎么用**（编辑模式下）：

1. 选中范围 —— 点中一条 bullet 的 **`✨ 用指令改`**（改一条）/ 单位标题旁的 ✨（改一段经历）/ 章节标题旁的 ✨（改整章）；
2. 写一句要求 —— 例如「缩短到两行以内」「突出量化成果」「按 JD 的『数据驱动』重写」「语气更专业」。也可以点下方的**常用指令**直接套；
3. AI **只改这一段**，返回后给你 **原文 vs 改写** 逐条对比；
4. 你可以 **应用到简历** / 关闭；不满意点 **再改改** —— 回到输入框改要求，AI **在上一版基础上继续改**（不推翻重来）。

**三条边界（和别的路径共用同一套底线）：**

| | 说明 |
|---|---|
| **范围严格** | 只改你选中的这一段，别的一个字都不动；条目还是条目、要点还是要点，`heading` / `meta` 这类事实字段原样保留 |
| **数字守恒照旧** | 服务端独立复算：改写里出现**选中范围原文没有的数字** → 逐条标出来（橙色「AI 补的数字」），提醒你核实 |
| **推断要登记** | 走「大胆 / 放手」风格时，AI 补的量化值必须给依据（`inferred_facts`），UI 里逐条列出 |
| **可回滚** | 应用时自动存一个「AI 改写版 · 指令改写」快照，随时在「版本」里切回 |

> 一条链路有测试钉着（第 27–28 套）：提示词边界、三种作用域的写回（bid 复用 / 新增）、迭代、
> 以及"AI 补的 40% 会被服务端标出来"。

### 换个模板导出

解析出的 JSON 可以直接套内置模板，换成一套干净统一的样子。**样式由我们自己给，不从原 PDF 还原** ——
原简历排版未必好、ATS 未必读得了；模板是产品资产，一次做好所有简历都受益。

**在工作台里**：点顶部工具栏的 **「换模板」** → 选模板、选配色 → 预览 / 导出 HTML / 导出 PDF。
渲染在本地服务里完成（不联网），**内容一个字都不改，只换排版**。
底层走 `GET /api/templates` 取模板清单、`POST /api/render` 拿渲染好的 HTML，
再交给已有的 `/api/export-pdf` 出 PDF —— PDF 链路只维护一份。

**导出排版可调**（模板弹窗的「排版」区）：

| 选项 | 说明 |
|---|---|
| 字体 | 模板自带 / 黑体 / 宋体 / 楷体 / 思源宋体 |
| 字号 | 小 / 标准 / 大 / 更大（0.95–1.1，整体缩放，和「自动压页」的缩放相乘） |
| 行距 | 紧凑 / 标准 / 宽松 / 更宽松（1.5–2.0） |

> 这三项会写进最终 HTML 的 CSS（`POST /api/render` 的 `font` / `font_scale` / `line_height`），
> 导出 HTML、预览、导出 PDF 走的是同一份，所以三者永远一致。

**层级与分页**：
- 「项目工作：」是**项目内的小标题**（正文加粗），**不是**「工作经历」这种大节 ——
  不会带竖线/下划线，也不会比模块标题更抢眼；
- `@page` 有 **10mm 纵向页边距**，跨页时上下页都有留白（`@page` 的 margin 是每页生效的，
  `.page` 的 padding 只在首尾页生效，所以必须写在 `@page` 上）；
- 每个 `.block` 有 `break-inside:avoid`，不会把一个项目从中间切开。

**命令行**（不开应用也能用，还能一次出全套对比）：

```bash
# 看有哪些模板
python tools/render.py --list

# 三套模板一次全出，并顺手导出 PDF
python tools/render.py 我的简历.pdf --all --pdf -o out/

# 只出某一套；也可以直接吃已有的 JSON（不重新解析）
python tools/render.py 我的简历.json -t modern -o out/
```

| 模板 | 特点 |
|---|---|
| `classic` | 经典单栏，姓名居中。最通用，ATS 友好，不抢戏 |
| `compact` | 紧凑单页。姓名左、联系方式右，字号小但层次清楚，内容多时压得进一页 |
| `modern` | 现代分栏。左侧深色信息栏（联系方式 + 技能/荣誉），右侧主体经历 |
| `vibe-standard` | 图标章节标题 + 渐变横线、经历时间轴、技能双列（蓝色系） |
| `vibe-dense` | 高密度，蓝色章节标题 + 细分隔线，内容多时首选 |
| `vibe-research` | 深蓝稳重、少装饰，突出科研与论文 |

后三套**移植自 [vibe-resume](https://github.com/LiuMengxuan04/vibe-resume)** 项目
（`templates/internship-employment/` 和 `templates/research-application/`）。
移植原则是**只搬设计语言、不搬 DOM** —— 那边每套是手工填好的整页 HTML，
我们这边数据是结构化的，所以用同一套 DOM + 各自的 CSS 复刻它的视觉；
配色接入我们的变量体系，**移植后依然可以用 `--theme` 换色**。
章节标题的图标（学士帽 / 公文包 / 代码 / 工具 / 文件）取自它同款的 SVG sprite，
按章节名关键词自动选（认不出就退回通用文件图标）。

导出 PDF 走本机 Chrome / Edge 的无头打印（A4），导出后**会报页数**，超过 1 页会标 `⚠` 提醒。

> 模板层**一个字都不改**内容，只负责排版。所以换模板、调样式，永远不会影响内容准确性 ——
> 这就是把"解析"和"呈现"拆开的意义。每个要点都带 `data-bid`，可以反向定位回原数据。

#### 自动压到一页

内容多的简历套上新模板可能从 1 页涨到 2 页。工作台「换模板」面板里默认开着
**「自动压到一页」**：内容超出 A4 时整体缩小，刚好放进一页。

缩小是**按比例整体缩**（不是只缩字号）—— 因为只缩字号试过：缩到 80% 才降 11% 高度，
远远不够（间距没跟着缩）。用 `zoom` 连带宽度一起缩之后，布局与原来完全等价，
高度就是原高度的比例倍，可预测。

缩放**一定会告诉你**（"为压进一页整体缩到 79%"），不会悄悄把字变小。

> 内容实在太多时，即使缩到下限 62% 也放不下 —— 这时建议换 `compact` / `vibe-dense`
> 这类紧凑模板，或者精简内容。硬缩到 50% 已经不像简历了。

命令行同样支持：

```bash
python tools/render.py 我的简历.pdf -t vibe-standard --fit --pdf -o out/
```

#### 换配色（内置 5 套 + 任意改）

模板里所有颜色都走 CSS 变量，所以换配色不用动模板本身：

```bash
# 预设：slate（默认灰蓝）/ ink（纯黑灰）/ teal（青绿）/ wine（酒红）/ amber（琥珀）
python tools/render.py 我的简历.pdf --all --theme wine -o out/

# 也可以逐项覆盖（改哪几个就传哪几个）
python tools/render.py 我的简历.pdf -t modern --theme accent=#b45309 -o out/
python tools/render.py 我的简历.pdf -t classic --theme accent=#0f766e,line=#cbd5e1 -o out/
```

可覆盖的 key（定义在 `tools/templates.py` 的 `DEFAULT_THEME`）：

| key | 管什么 | key | 管什么 |
|---|---|---|---|
| `ink` | 标题 / 强调文字 | `line` | 分隔线 |
| `deep` | 深色侧栏底、强分隔线 | `accent` | 强调色（图标徽章） |
| `body` | 正文 | `side-text` | 深色侧栏上的文字 |
| `sub` | 次要文字 | `canvas` | 纸张外的底色 |
| `meta` | 日期 / 地点 | `faint` | 圆点 / 极弱信息 |

#### 自定义哪些章节进侧栏

modern 模板默认把"技能 / 证书 / 荣誉 / 奖项 / 其他 / 自我 / 兴趣 / 语言"类的章节放左栏。
想改就传 `--side`：

```bash
python tools/render.py 我的简历.pdf -t modern --side "荣誉,证书,教育经历" -o out/
```

#### 加一个新章节（内容模块）—— 不用改任何代码

模板是**遍历 `sections`** 渲染的，不认识具体章节名。在 JSON 里加一段：

```json
{ "title": "播客与写作", "blocks": [
    { "heading": "《AI 应用观察》", "date": "2024.01 – 至今",
      "bullets": [{ "bid": "p10-b1", "text": "更新 12 期，累计播放 8000+。" }] }] }
```

它就会出现在简历上（三套模板都支持）。唯一受配置影响的是"进不进侧栏"（见上一条）。

#### 加一套新模板（开发者）

`tools/templates.py` 里加三样东西就行，全程零第三方依赖：

1. 一个 CSS 常量 —— 引用 `var(--c-*)` 变量，就自动支持上面所有配色
2. 一个 `body` 函数，拼出 header + 各章节（可复用 `_hdr_block` / `_section_html`）
3. 在 `_TPL` 里注册：

```python
"mytpl": {
    "name": "我的模板",
    "desc": "一句话说明",
    "css": CSS_MYT,
    "body": _body_myt,
    "theme": {"accent": "#2563eb"},   # 可选：这套模板自带的默认配色
},
```

现有六套就是这么堆出来的，`--list` 会自动列出来。
配色优先级：**命令行 `--theme` > 模板自带 `theme` > 全局 `DEFAULT_THEME`**。

## 七、常见问题

**页面显示「离线模式」**
没连上本地服务。检查 `start.bat` 的窗口是否还开着；或点设置里的「重新检测」。

**「还没有粘贴目标 JD」**
工作台右侧顶部的「目标 JD」框是空的。评估必须知道目标岗位才能按它改写。

**上传 PDF 提示扫描件**
图片型 PDF 没有文字层。改用「粘贴简历文本」（从 PDF 里全选复制即可）。

**解析出来的结构不对（要点被拆成好几条 / 章节顺序乱 / 单位名多了个怪字符）**
先确认**服务重启过没有** —— 解析器是服务端代码，`start.bat` 启动后改代码不会热加载。
重启还不对的话，多半是**没装 PyMuPDF**（走的还是"纯文本 + 猜"）。装一次就好：

```bash
python -m pip install --target D:\workbuddy\temp\pylibs pymupdf
```

装完重启服务，`http://127.0.0.1:8420/api/health` 里 `structured_ok` 会变成 `true`。
想先单独验证某份 PDF 能不能解析好：`python tools/pdf2html.py 简历.pdf`，然后打开产出的 HTML 看「版面核对」视图 —— 哪一行颜色不对，就是那里判错了。

> **注意 PyMuPDF 是编译扩展**：给某个 Python 版本装的，换解释器可能就用不了
> （`start.bat` 用 `where python` 找第一个可用的）。想确认当前服务用的哪个 Python，
> 看 `/api/health` 的 `python_exe`。

**解析时提示「结构重建中断 / 输出达上限」**
长简历的 NDJSON 输出体积和正文同量级，一次就能顶到模型输出上限（推理型模型如 MiniMax-M3、
DeepSeek-R1 的思考过程还要先吃掉一部分额度）。现在这条链路是这样处理的：

1. **截断不再当失败** —— 已还原的章节照样拿得到
2. **自动接着还原** —— 服务端发现被截断，就带着"已还原到哪"再请求一次，最多接 4 段，并自动去掉重复章节
3. **真接不完时** 弹窗里给两个出口：「先用已还原的部分」/「继续补齐剩余章节」

所以正常情况下你不会再看到这个提示。如果还看到，按顺序试：
① 点「继续补齐剩余章节」；② 设置里换一个输出上限更大的模型；③ 用「粘贴简历文本」并只贴核心经历

**上传 PDF 提示「未安装 PDF 解析库」**
正常情况下不该出现 —— pypdf 已随项目放在 `libs/`，任何 Python 都能用。
如果真遇到，检查两件事：

1. `libs/` 目录是不是丢了（比如拷贝时漏了）→ 补回来：`python -m pip install --target libs pypdf`
2. 打开 `http://127.0.0.1:8420/api/health`，看 `pdf_lib_ok` 与 `pdf_lib_source` 两个字段

**想确认服务用的是哪个 Python**
打开 `http://127.0.0.1:8420/api/health`，看 `python_exe` 字段；启动窗口的自检信息里也有「解释器」一行。

**深度重写报「返回格式异常 / 模型没有按约定格式返回整段结果」**
界面上会区分两种原因：
- **提示「被长度上限截断」** → 模型把额度花在思考上、整段没写完。处理：换输出上限更大的模型、
  关掉该模型的思考 / 推理模式，或先在简历里只留 1–2 个项目再重写。
- **提示「没有按约定格式返回」** → 模型的输出形状不对。原始输出已自动存到
  `logs/deep-rewrite-raw.txt`，打开就能看它到底返回了什么（也欢迎把它发给开发者）。

> **历史坑（已修）**：模型（如 glm 系列）把整段 JSON **美化输出成多行**时，旧的增量解析器按行切，
> 会把这种对象的每一行都当噪声丢掉，整段再也拼不回来 → 误报"没返回结果"。
> 现在解析器改成**大括号配平扫描**：单行 NDJSON / 美化多行 / 该换行没换行 / ```json 包裹一律通吃
> （第 24 套测试把这条钉死）。

**测试连接失败**
- `API Key 问题` → 检查 Key 是否填对、是否与所选服务商匹配
- `网络不通` → 该服务商可能需要代理，或 Base URL 写错
- `请求被拒绝` → 多为模型名不支持，去「高级选项」换模型

**导出 PDF 失败**
可以先用「导出 HTML」，然后在浏览器里 Ctrl+P 自己打印成 PDF。
